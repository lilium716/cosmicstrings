# PINN と RBF による学習

## 目的

RK4 の計算結果を学習データにして PINN（physics-informed neural network）で学習し、ある程度学習できたらデータを外して、方程式（物理）だけで学習を続けられるかを調べる。比較として、ニューラルネットワークの代わりに時空のガウス型動径基底関数（RBF）を使う方法も試す。

## 条件

- 方程式: φ″ + 2ℋφ′ − ∇²φ + a²λ(|φ|² − η²)φ = 0（輻射優勢期 a = τ/20、λ = η = 1）
- 学習データ: `2026-10-21_global_string_flrw` と同じ設定の RK4（`data/rk4`、τ = 0.5 ごとに φ と π = φ′ を保存）
- 窓: x ∈ [−8, 8]、y ∈ [−6, 6]、τ ∈ [32, 42]（衝突と対消滅を含む）。格子 128×96
- 損失（重み）: 物理 = 方程式の残差の 2 乗平均（1）、初期条件 = τ = 32 の φ と φ′（10 ずつ）、境界条件 = 窓の縁の φ（10）、データ = 窓の内部の φ（10、整数の時刻 τ = 33, …, 42 のみ）
- 評価: 保存した全時刻（τ = 32, 32.5, …, 42）の窓内全格子点での、RK4 との相対 L2 誤差。半整数の時刻は学習に一度も使っていない検証用
- 学習のしかた
  - データ → 物理のみ: データあり（4 つの損失）で学習し、データ時刻の誤差が 2% を下回ったらデータを外す
  - 物理のみ: 最初からデータを使わない
  - データ + 物理: 最後までデータを使う
- 注意: 「データを外した後」や「物理のみ」でも、境界条件として窓の縁の RK4 の値を全時刻で与えている

### PINN

- ネットワーク: (x, y, τ) → (Re φ, Im φ)。ランダムなフーリエ特徴量（128 個、σ = 1）+ tanh の全結合層（幅 128、4 層）、パラメータ 82,690 個
- Adam、学習率 1e-3 から指数的に下げて 1e-4、10000 反復、1 反復あたり物理 4096 点・初期条件 2048 点・境界 2048 点・データ 4096 点
- PyTorch 版（`pinn.py`、Mac の GPU、単精度）と tenferro-rs 版（`src/bin/pinn.rs`、CPU 4 スレッド、倍精度）

### RBF（`rbf.py`）

- φ = Σ W[a, b, c] g_a(x) g_b(y) g_c(τ)、g はガウス関数。中心は空間 0.25・時間 0.25 間隔の格子（67×51×43）、幅は中心の間隔と同じ。未知数 293,862 個
- ガウス・ニュートン法（10 回）。各ステップの線形最小二乗は正規方程式を共役勾配法（300 回）で解く
- 物理の残差は Δx = 0.125、Δτ = 0.125 の格子で評価
- 出発点: データありはデータ・初期条件・境界条件だけを当てはめた解、物理のみは τ = 32 の φ を時間方向にそのまま伸ばしたもの

## 結果

RK4 との相対 L2 誤差（データに使った時刻の平均 / 検証用の時刻の平均）:

| 学習のしかた | PINN（PyTorch） | PINN（tenferro-rs） | RBF |
| --- | --- | --- | --- |
| データ → 物理のみ | 3.1% / 2.7% | 2.2% / 1.9% | 4.3% / 3.8% |
| 物理のみ | 37% / 32% | — | 22% / 17% |
| データ + 物理 | 0.36% / 0.46% | — | 0.62% / 1.17% |

計算時間: PINN（PyTorch）1 本 約 25 分、PINN（tenferro-rs）約 2.4 時間（RBF と CPU を分け合った）、RBF 1 本 14〜28 分。

- データを外すと、どの方法でも誤差は 2% から 3〜5% に上がる。PINN はその後物理だけで少しずつ下がった（PyTorch 5% → 3.1%、tenferro-rs 4% → 2.2%）。
- 物理のみでは、どの方法でも RK4 の解を再現できない。誤差は初期時刻から離れるほど増える。RBF は対消滅の前（τ < 37）までは誤差 8% 以下に保つが、対消滅後に 70% まで悪化する。
- PINN の方程式の残差は、データ → 物理のみとデータ + 物理でほぼ同じ（3×10⁻⁴）なのに、RK4 との誤差は 10 倍違う。残差が小さいことは解が正しいことを保証しない。
- RBF はガウス・ニュートン法 5 回程度で収束し、PINN の 1 万回の学習より速く精度の良い解に届く。ただし残差は 2.7×10⁻² で止まり、検証用の時刻（半整数）の誤差がデータ時刻より大きい。中心の間隔 0.25 がひものコア（幅 0.35〜0.45）に対して粗いことが、精度の上限になっていると考えられる。
- PINN の tenferro-rs 版は PyTorch 版と同じ振る舞い（反復 750 でデータを外す、その後の誤差の推移）を示した。
